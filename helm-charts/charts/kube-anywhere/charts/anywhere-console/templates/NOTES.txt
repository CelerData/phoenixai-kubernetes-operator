Anywhere Console accounts live in the Secret "{{ template "anywhere.adminSecretName" . }}"
(key = username, value = password).
{{- if and (not .Values.admin.existingSecret) (not .Values.admin.users) }}
A single "admin" account was generated with a random password. Retrieve it with:

  kubectl -n {{ .Release.Namespace }} get secret {{ template "anywhere.adminSecretName" . }} -o jsonpath='{.data.admin}' | base64 -d; echo

NOTE: this default relies on `helm lookup` and must not be used with GitOps/ArgoCD or
`helm template` pipelines (each sync would re-randomize the password) — set
admin.users or admin.existingSecret there instead.
{{- else if eq (index .Values.admin.users "admin" | default "") "admin" }}

WARNING: this install carries the chart's default account admin / admin. That password is
public — replace it before anyone else can reach the console:

  kubectl -n {{ .Release.Namespace }} edit secret {{ template "anywhere.adminSecretName" . }}
{{- end }}
Add, remove or rotate accounts with `kubectl -n {{ .Release.Namespace }} edit secret {{ template "anywhere.adminSecretName" . }}`;
changes take effect within about a minute, no restart needed.
{{- if include "anywhere.viewersEnabled" . }}

Read-only (viewer) accounts live in a second Secret, "{{ template "anywhere.viewerSecretName" . }}"
(same format). A viewer sees everything an administrator sees but cannot change commands, exec
presets or licenses, run arbitrary commands, or download support bundles. Add a read-only account
there, not in the Secret above — a username in both is an administrator when it signs in with
the password the Secret above gives it:

  kubectl -n {{ .Release.Namespace }} edit secret {{ template "anywhere.viewerSecretName" . }}
{{- end }}

The Cluster Console is a second sign-in page, at /cluster-console/login, for the people who query
a cluster rather than operate the fleet: select a cluster there, then use that cluster's own
PhoenixAI Database username and password. No Anywhere Console account is involved, and the two
consoles keep separate session cookies, so one browser can hold both sessions at once.
